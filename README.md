# PlotInjector 剧情注入器

个人自用的 SillyTavern 酒馆助手脚本，不提供支持，不接受需求与问题反馈。

当前版本：v0.3.7

本版包含截至 2026-11-17 的导入与统一审阅功能，保留聊天项目绑定、人设、无限流、多卷写作、阶段调整和世界书工具。使用方法见 [线索模式使用说明](docs/线索模式使用说明.md)，本次升级和行为变化见 [v0.3.0 升级说明](docs/v0.3.0升级说明.md)，更早版本的迁移规则见 [v0.2.0 升级说明](docs/v0.2.0升级说明.md)。

## 功能

- 「项目」保存一个故事的设定、人设、大纲和进度，绑定到角色卡和聊天使用：每个聊天同时使用一个项目，新聊天用本卡默认项目；主线、支线都写在同一个项目的大纲里。按 讨论 → 设定 → 人设 → 大纲 → 执行 五个页签推进，设定和人设可选
- 讨论：与 AI 多轮讨论剧情，可附带世界书条目、当前设定和大纲作参考；长讨论自动折叠成摘要，可导出后清空
- 设定：AI 按内置写作基准整理世界观正文，新旧稿按分块对比采用，保留最近 10 个历史版本
- 大纲：剧情 YAML（卷 → 阶段 → 节点）导入、编辑、导出；AI 可连续写 1–5 卷，支持细化、拆分、合并阶段；格式错误时指出行号并可让 AI 修正
- 线索模式：按表格中已经发生的事实开放节点，只提供当前可以使用的场景材料；同一场景可以跨多楼进行
- 多线剧情：主线串行、支线名额与排队、进入证据、时段与表格条件；支持暂停、恢复、切换和离场记录
- 导入与审阅修改：长文按一条主线、一条支线或多条支线整理；导入和修改已有剧情线用同一个逐页审阅页（外层选线、内层按阶段翻页），各页写意见一次发给 AI，改完先进草稿，确认后保存到大纲；编号冲突、依赖关系、找不到的条件都会检查
- 跑团模式（实验）：设置页「实验功能」打开后可新建跑团项目。导入 PDF 模组，整理出带检定的线索节点和 KP 规则；检定由玩家掷骰，插件按 CoC 7 版规则判成败，成功后才把线索交给正文
- 人设：分阶段注入，支持手动、跟随剧情阶段、读 IGS 数值和条件检测；可从世界书转入、单独导入导出
- 创作辅助：讨论后用「审阅修改」改剧情线、一键生成配套线索表格；正文写作提示已内置，可编辑或关闭
- 执行：设定和当前阶段详细以常驻虚拟世界书条目注入，位置、深度、角色、顺序规则与世界书一致；详细条目注明是尚未发生的剧情规划
- 推进：每 N 楼由进度检测模型对照剧情索引（只给检测用，不注入正文）判断节点是否发生；可选询问、自动推进、只勾节点
- 偏离：检测发现剧情严重偏离大纲时提醒或自动改写后续阶段，改写可撤销
- 每个聊天可以单独指定使用的项目，也可设置本卡默认项目；进度随聊天保存
- 项目打包：数据管理页「导出完整项目」，带上大纲、线索标签、保密名单和推进设置，人设、设定可选；在别的酒馆用「新项目 → 从文件导入」。卡作者可以把写好的剧情和角色卡一起发给玩家
- 数据全部存在酒馆本地 `user/files/pi-*`，浏览器只记界面状态；数据管理页可单删、清理孤立文件、全部清除（先下载备份），世界书管理页直接修改角色卡世界书：条目开关、删除、编辑位置与关键词和内容，TavernDB-ACU 数据库条目按字段折叠开关

## 安装

在酒馆助手中导入 `loader/plot-injector.json`，点击 QR 栏的「剧情注入」按钮打开。

加载器启动时读取本仓库最新的版本标签（缓存 30 分钟），无需重复导入。设置页可锁定某个版本标签，或填 `main` 使用最新提交。

不联网更新时可导入 `dist/plot-injector-standalone.json`（内嵌完整程序）。

本版新加载器在找不到不低于本构建版本的标签时使用 main，有新标签再跟随标签。旧加载器仍遵循原版本逻辑，可在「数据管理 → 版本更新」填 `main`，或重新导入本版加载器。

## 要求

- SillyTavern 1.13 以上（需要 `SillyTavern.libs.yaml` 与世界书条目加载事件；没有该事件时退回为专用世界书）
- 酒馆助手（JS-Slash-Runner）

## 开发

```text
npm ci
npm run build   # 生成 dist/ 与 loader/plot-injector.json
npm test        # 构建、核心逻辑、模拟宿主、官方数据库接口兼容测试
node templates/clue-tables/build-template.mjs  # 重建随包表格模板
```

### v0.3.8

- 🎲 **跑团模式新增「KP」卡（执行页）。** 「这局还顺吗」推演凭已拿到的线索主线能否走通，先给不剧透的结论，展开后才显示具体节点；判定失败、无法补救的线索不算在内。

- ✨ **线索标签填写更清楚。** 「自动填写」有进度条，填完自动保存；标签没填完时主按钮变灰，并写明还差几条。
- 🔍 **请求核验指明泄露位置。** 命中的内容来自设定还是表格，会直接写出来，方便定位修改。

### v0.3.4

- 🎲 **新增跑团模式（实验，CoC 7 版）。** 在设置页「实验功能」打开后，新建项目时可以勾选「跑团模式」。不打开时界面和线索模式完全一样。
- 📄 **长文导入能读 PDF。** 跑团项目的导入页可以直接选 PDF 模组，读文字层后还原段落、标题、项目符号和双栏排版，目录页跳过，图片页会提示。扫描版 PDF 暂不支持。
- 🧩 **模组拆成带检定的线索。** 勾选「跑团模组」整理时，需要检定才能拿到的线索写成带「判定」的发现；理智检定、战斗、计量、时间线、随机表和 NPC 数据另外整理成设定里的「KP规则」分块。
- 🔒 **线索在掷骰成功后才交给正文。** 掷骰前，正文只知道这里可以过什么检定，看不到线索内容。正文写出检定请求后停下，玩家在自己的消息里给出骰点，插件在这一轮拼提示词时按 CoC 规则判成败：成功才把线索放进同一个请求，失败只给失败的后果。同一个检定以第一次的结果为准。检定写法可选正文文字或论坛安科（配合 IGS 论坛的「检定」安科，点一下就能掷）。
- 🔍 **审阅页「AI 检查」。** 跑团导入的审阅页可以让 AI 对照模组原文，查漏写的检定、会卡住主线的判定、提前剧透等问题，结果写进各页意见，确认后照常按意见修改。

### v0.3.3

- ✏️ **新聊天也能改线索标签。** 聊天还没填过表时，表格里只有模板带的初始行，没法直接写。现在改动会先存进项目，聊一轮、数据库填过表以后再打开「改线索标签」点保存，就写进表格。以前这种情况会全部报「没写进表格」。刷新页面后，和项目里存的不一样的条目也会自动带出来。
- 🌐 **认得改过名的全局表。** 以前只认名字叫「全局数据表」的表，卡里叫「全局状态表」之类时，没改成每楼更新，时间条件和执行页的当前位置也读不到。现在按名字和列一起认：「全局数据表」「全局表」「全局状态表」，或名字带「全局」、有时间列的表；时间、地点按常见列名找。列多列少都不影响，插件只改它的更新频率，不增删列、不改它的规则。已经导入过的聊天，再点一次「生成线索模板」就会补上。
- 🏷️ **登记口径的状态写法更稳。** 表格的状态只有「已核实」「存疑」两种。生成标签时会照这个写；口径里写成「记为传闻」「记为推测」时，弹窗会标黄提醒改成「记为存疑」。
