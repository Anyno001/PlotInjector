# v0.2.0 升级与开发说明

本版在模块化仓库中整合上游 v0.1.34 和截至 2026-11-16 的线索、多线、剧情承接及实测返修。保留上游的人设、无限流、支线钩子、进度钟、阶段操作和世界书工具。

## 安装和已有数据

升级前可从数据管理导出备份，并备份酒馆聊天。导入 `dist/plot-injector-standalone.json` 即可离线使用；脚本 ID 延续原版，避免同时启用重复实例。项目仍保存在 `user/files/pi-*`，进度仍保存在聊天的 `chat_metadata.plotInjector`。

本次没有创建版本标签。新加载器在没有达到本构建版本的标签时加载 main；正式新标签出现后优先使用标签。旧加载器可在「数据管理 → 版本更新」指定 main，或重新导入 `loader/plot-injector.json`。明确指定的旧标签仍按用户选择加载。

| 旧数据/设置 | 读取与迁移 |
|---|---|
| 没有线索字段的旧项目 | 默认大纲推进，不自动切换线索模式 |
| 没有人设配置 | 补空人设结构；不新增人设检测请求 |
| 没有多线元数据 | 延续单线场景逻辑；不强制改成多线 |
| 缺少支线名额、提示开关 | 默认同时 1 条支线、启用顶端提示；可在执行页调整 |
| 旧位置节点编号 / 开发版 `@节点id` | 使用节点稳定编号和上游改名/阶段对照表对齐；移动、改名、拆分阶段的已演标记跟随原事件 |
| 旧 `inject: link`、`waitFill` | 读取时统一为临时世界书，忽略等待字段，保存后清理；其他线索设置、事实和进度保留 |
| 旧自定义写作基准 | 识别为自定义；未填写时使用通用基准，可切换同人或自定义 |
| 老表格或不同表名/列名 | 按实际绑定读表；生成模板前预览，保留已有数据。无法匹配时报告原因，不把缺表当作事实不存在 |
| 旧人设进度 | 沿用上游按阶段编号/名称对齐；线索、承接、逐楼入口记录与人设字段可同时保存 |

没有对应事件的已演标记不会转移给同名新事件；删除或改写历史前应检查界面提示及备份。不同聊天各自保留项目绑定和进度。绑定支持宿主的 `getCurrentChatId()` 和旧 `chatId` 两种接口。

## 有意改变的行为

- **官方数据库路径统一。** 不再注册实验 Plot Link provider，不等待不可可靠获知的填表任务状态。正文使用最近已提交表格，入口识别使用本轮名单和官方填表记录证据。填表还未完成时连发下一轮可能暂用旧状态。
- **多块 YAML 不再只取第一块。** 多个合法且顶层卷名不同的块会合并，避免批量导入时丢线。强制全块解析仍会报告坏块；预览和采用检查继续有效。
- **进入与推荐分开。** 多线中提示入口不等于已经进入，支线按进入证据、条件或手动操作开始。已有单线项目的自动焦点行为保留。
- **离场有明确值。** 控制表写「无」、配置的离场值或「离场」后停止当前场景材料；空白仍按兼容逻辑处理，不等价于明确离场。已开始但暂时走开的线在卡片上提示离开轮数。
- **作废以当前数据为准。** 人工撤销压住事实和知情判断；SQLite 模式按事实编号写回，再回读确认。原生存储或回读失败会如实提示。解除作废只恢复按当前表格判断，不还原已清掉的内容。
- **人设与线索并存。** 人设关键词、数值和手动切换继续工作；跟随剧情阶段在线索模式读线索阶段状态，不改写大纲模式进度。大纲模式仍按设置定期检测；线索模式的人设条件通过「立即检测」检查，正常回合不额外调用检测模型。

## 源码与构建

- `src/core/lines.js`：名额、排队、进入证据、场景目录及官方填表记录的纯逻辑。
- `src/core/clue-*`：编译、三值条件、事实与知情投影、跨楼记录、模板与核验。
- `src/app/clue-runtime.js`：官方数据库回调、回合隔离、场景目录同步、补行和作废写回。
- `src/core/long-import.js`、`src/ui/line-review.js`：按线导入、冲突检查、意见修改和逐线采用（v0.2.0 时的结构；之后改为统一审阅页 `src/ui/long-import.js`、`import-review.js`、`review-lines.js`）。
- `src/host/files.js`：按文件串行保存；`flush()` 等待在途上传和后续待写内容。
- `src/core/personas.js`：保留人设核心，通过可选阶段状态输入适配线索模式；承接和人设参数在 `buildEntries` 边界合并。

使用 Node.js 22.13+（或受支持的新版本），执行 `npm ci`、`npm test`。测试会先构建真实发布包，再跑纯逻辑和模拟宿主测试。`npm run test:official` 保留为同一完整测试入口。随包模板用 `node templates/clue-tables/build-template.mjs` 重建。

当前仓库没有独立 lint 配置、TypeScript 或类型检查命令；构建和 JavaScript 语法检查不能替代完整类型检查。自动测试不调用付费模型，也不代表真实酒馆主题、不同数据库版本及模型填表准确性已经全部验证。
