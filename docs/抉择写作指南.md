# 抉择写作指南

给写卡作者看：怎么在线索模式的大纲里写「抉择」和「收尾」，让剧情有分支、有结局。

先在设置 → 高级勾「抉择与结局（实验，线索模式）」。没勾时这些字段会被忽略，插件和以前一样。

## 一、先想清楚：什么时候用抉择

**适合**：玩家要做一个关键决定，而且选不同的路，后面会不一样。例如：
- 救人：潜入，还是谈交易？
- 站队：帮镇上的人，还是帮土匪？
- 方向：先去灯塔，还是先去修道院？

**不适合**：
- 调查、问话、搜查：照常写成节点和发现，玩家自己决定去哪查。
- 只换一句话、后面完全一样的「假选择」。
- 日常对话里的小决定：玩家直接打字就行。

**数量**：一条线 1～2 处就够。抉择太多，玩家会觉得在做选择题，正文也容易被打断。

## 二、最小写法

在节点上加「抉择」，至少两个行动：

```yaml
- id: n_letters
  名称: 两封信
  入口: 读刚送来的两封求助信
  场景: 灯塔看守和修道院同时来信求助
  抉择:
    情境: 两封信摊在桌上，只能先去一处
    选项:
      - 行动: 先去海边的灯塔
      - 行动: 先上山去修道院
```

- **行动**：玩家口吻的一个具体做法。会显示在卡片上，玩家点了会变成输入框里的一句「我决定……」。不写后果，不写难度。
- **情境**：卡片顶上的一句，可以不写。
- **选项编号**：不用写，保存后插件自动补上（如 `o3k9…`），之后不会变。想自己起名也可以：`id: lighthouse`，后面写条件时更好认。
- **带抉择的节点不写完成条件**：玩家选了、正文写完这一轮，它就算完成。

## 三、有风险的行动：写结果和骰子

行动可能失败时，加「风险」和三档「结果」：

```yaml
  抉择:
    情境: 雨夜的仓库，前门有守卫，后门虚掩着
    选项:
      - id: sneak
        行动: 绕到后门，找机会潜进去
        方向: 等守卫换班，从后门摸进去
        风险: 普通
        有利: [{事实: F_shift}]
        不利: [{事实: F_alarm}]
        用: 身手
        结果:
          顺利: 悄悄带出了人
          有代价: 人带出来了，但被看清了脸
          失败: 被发现，人被连夜转走
      - id: deal
        行动: 去找管事谈一笔交易
        方向: 管事贪财，开价很高
```

| 字段 | 说明 |
|---|---|
| 方向 | 给正文的一句做法提示，玩家看不到。不写就用「行动」 |
| 风险 | 容易 / 普通 / 困难，分别 +1 / 0 / -1。不写就不掷骰 |
| 有利 / 不利 | 条件列表，每满足一条 +1 / -1。适合写「之前查到的线索」，奖励调查周全 |
| 用 | 属性名（在执行页「当前抉择」→「属性…」里设），按属性值加 |
| 结果 | 三档都要写：**顺利**；**有代价**（目标达成，但付出代价）；**失败**（目标没达成，写出接下来的处境） |

**骰子怎么算**：两颗六面骰加上加值，总加值最多 ±3。合计 10 以上顺利，7～9 有代价，6 以下失败。

| 总加值 | 顺利 | 有代价 | 失败 |
|---|---|---|---|
| -1 | 8% | 33% | 58% |
| 0 | 17% | 42% | 42% |
| +1 | 28% | 44% | 28% |
| +2 | 42% | 42% | 17% |
| +3 | 58% | 33% | 8% |

加值 0 时失败有四成，所以：
- 「有代价」要写成真的达成了目标，不要写得和失败差不多；
- 「失败」要接一条能继续玩的路（见第四节）；
- 给玩家留几条「有利」线索，查得越周全越容易成功。

**正文只拿到选中的那一档**：没选的行动、别的档位，正文都看不到。玩家打字时选了「我有别的打算」自己想办法的，不掷骰，正文按情境写。

### 行动按条件出现、单个检定、不可回头

```yaml
  抉择:
    情境: 所有人都在等你的答复
    不可回头: 是                     # 卡片底部多一行小字「做了决定就不能回头」，不写后果
    选项:
      - id: guild
        行动: 站在商会一边
        条件: {表: 声望表/商会/态度 != 敌视}   # 满足才出现；读不到时也不出现
      - id: alone
        行动: 谁也不靠                 # 不写条件，永远出现，当兜底
```

- **行动的「条件」**：用来锁死某条路（某个势力已经和你敌对、关键人物死了），或者要求够格才出现。至少留一个不写条件的行动当兜底，否则作者检查会报错。
- **单个检定**：只有一个行动、而且它带「风险」时，可以只写这一个，比如「说服工头出人」。卡片上仍然有「我有别的打算」和「收起」，玩家不是被迫的。
- **已关闭**：后面的节点只读某个抉择的结果，而那个抉择已经选了别的，执行页会显示「已关闭：选了……」。

## 四、后续：让选择真的有影响

在后面节点、线的「开放条件」里读抉择：

```yaml
- id: n_chase
  名称: 追踪货车
  入口: 去码头路口截住转移人的货车
  必需: false
  开放条件: {抉择: n_rescue, 结果: 失败}

- id: n_debt
  名称: 管事上门讨人情
  入口: 管事派人来找你
  必需: false
  开放条件: {抉择: n_rescue, 选了: deal}
```

| 写法 | 意思 |
|---|---|
| `{抉择: n_rescue, 选了: deal}` | 选了这个行动 |
| `{抉择: n_rescue, 选了: 自定义}` | 玩家自己想了办法 |
| `{抉择: n_rescue, 结果: 失败}` | 骰出这一档（顺利 / 有代价 / 失败） |
| `{抉择: n_rescue, 选了: sneak, 结果: 失败}` | 两项都满足 |
| `{其中至少: 2, 条件: [{事实: F_a}, {事实: F_b}, {事实: F_c}]}` | 下面几条满足至少 2 条 |

和原来的条件随意组合：`{任一: [...]}`、`{全部: [...]}`、`{事实: …}`、`{表: …}`、`{线: … == 完成}`。

**分清两种「后续」：**
- **读选择**（`抉择 … 选了 / 结果`）：读的是「玩家做了什么、骰出什么」，是历史。
- **读线索**（`事实 …`）：读的是「世界上实际发生了什么」，由填表登记。

比如「能和被救的人说话」，应该读「人质获救」这条线索，而不是读「潜入顺利」：玩家也可能自己想办法救出了人，那时没有骰子结果，但填表会登记获救。

**互斥和并行：**
- 同一个抉择只有一个答案，所以「选了 A」开的线和「选了 B」开的线天然互斥。
- 想让几条路都能做，就别用抉择，写成几个「必需: false」的普通节点或支线。

**别把主线卡死**：主线的必需节点、阶段的进入或结束条件，不要只靠某一档结果。比如「只在潜入顺利时才开放的必需节点」，失败的玩家就永远走不下去。作者检查会对这种写法给出提示。失败可以让人遗憾，但后面要有路走。

## 五、收尾和结局

在最后一个阶段加一个收尾节点：

```yaml
- id: n_end
  名称: 尾声
  入口: 回到码头
  开放条件: {节点: n_rescue}
  收尾:
    结局:
      - 名称: 真相在手
        条件: {其中至少: 2, 条件: [{事实: F_saved}, {事实: F_why}, {事实: F_truck}]}
        要点: 人救了回来，你也弄清了商会扣人的原因
      - 名称: 平安归来
        条件: {事实: F_saved}
        要点: 人回到了老周身边，码头上没人知道那晚发生了什么
      - 名称: 雨停了
        要点: 事情暂时没有结果，老周一夜没合眼
    尾声:
      老周:
        - {条件: {表: 重要角色表/老周/状态 == 死亡}, 要点: 码头工人为老周守了七天灵}
        - {条件: {抉择: n_rescue, 选了: deal}, 要点: 老周欠下商会一笔人情}
        - {要点: 老周回到码头，照旧骂骂咧咧}
      商会:
        - {条件: {事实: F_why}, 要点: 商会私运的事传开了}
        - {要点: 商会照旧做着它的生意}
```

- **结局**从上往下挑第一个满足的，最后一个不写条件，是默认结局。要求越高的结局放越前面。
- **尾声**分段写，每段各自从上往下挑一个版本，最后一个是默认。各段互不影响，不用把所有组合都写一遍。
- **主结局只写整体局势**；某个人物、某个地方的结果写在尾声里对应的一段，避免两处写出矛盾的话（比如主结局写「大家平安」，老周那段却写「守灵」）。
- **关键人物的生死、关系**由数据库的人物表记，结局直接读那一列（`{表: 重要角色表/老周/状态 == 死亡}`）。这需要你的数据库模板里有这一列，填表说明写清楚怎么填。
- 收尾节点不写完成条件；玩家点「结束这段故事」发送后就算完成。

**写完用「结局预览」检查**：大纲页「⋯」→「结局预览…」，假设选了什么、骰出什么、拿到哪些线索、表格某一格满不满足，看会落到哪个结局。

## 六、常见问题

| 问题 | 原因和改法 |
|---|---|
| 卡片没出现 | 场景没被认出来（剧情推进偶尔漏判，原生存储没有推进判断）。执行页「当前抉择」点「打开」 |
| 正文已经自己把事办了 | 执行页「当前抉择」点「标为已处理」，节点完成，不掷骰 |
| 选项结果被正文当成已经发生 | 结果写进了节点的「发现」。结果只写在「结果」里，发现只写调查能查到的东西 |
| 某条后续永远不开 | 条件读的是「选了」，玩家却用了自己的办法。改成读线索，或写 `{任一: [选了 …, 事实 …]}` |
| 收尾一直不出现 | 执行页会列出读不到的依据（表或列不存在）。修好，或点「按现有记录收尾」 |
| 作者检查说「只在某一档开放」 | 主线的必需节点只靠一档结果，失败会卡住。改成「必需: false」，或补一条别的路 |

## 七、让 AI 帮你写

开关打开时，写大纲的 AI 会知道抉择怎么写：

- **长文导入**：原文写了「玩家在这里要选择」「几种结局」才会写成抉择和收尾。
- **AI 写第 N 卷**：在要求里写清楚，比如「中间有一处关键抉择，其中一个做法可能失败；最后两三种结局」。AI 一条线大概写 1～2 处。
- **审阅修改、改写后续、阶段调整**：已有的抉择和收尾会原样保留，选项编号不变。要改就在意见里明说。

AI 写完一定要看一遍：
- 每个选项后面有没有不同的后续；
- 失败之后有没有路走；
- 用「结局预览」试几种情况。
