# 线索模式使用说明

## 安装与升级

1. 在旧插件的数据管理页导出备份，同时备份准备测试的酒馆聊天。
2. 在酒馆助手中导入 `dist/plot-injector-standalone.json`，启用这一份脚本，关闭旧的重复实例。
3. 打开插件，在执行页按项目选择「大纲推进」或「线索推进」。无限流项目保留原有入口。

本版是 v0.4.0。完整包可直接使用；本版新加载器在没有对应新标签时使用 main。旧加载器可指定 main 或重新导入。详细迁移规则见 [升级说明](v0.2.0升级说明.md)。

旧版不认识 `<仅作者>` 标签。回退旧版本时，应同时恢复升级前的项目备份，避免把新增的作者资料作为公开设定注入。

## 开始一段线索剧情

先在大纲页导入线索大纲，或使用「AI 写第 N 卷」。线索模式按节点的开放条件和完成条件推进；节点包括稳定编号、入口、场景、发现等字段。可以参考 `templates/clue-tables/示例_小镇失窃案.yaml`。

在执行页点「创建模板」（当前聊天还没有线索表时，「需要处理」里会直接给出这个按钮；也可以在「运行设置」→「线索表格」里找到）。插件读取当前聊天的数据库模板，预览新增的三张线索表、开局要用的事实行和人物表调整；确认后写入当前聊天。已有表格中的内容继续保留。后面新增剧情时，用「补全表格」补充新编号；已经有线索表时再点「创建模板」，写完会接着打开「补全表格」。

已经聊了一段才开始用线索模式时，插件会让线索表从当前楼层开始记，不从第 1 楼逐批补填。以前楼层里已经发生的事不会补登记，需要的话在节点菜单里手动标记。

表格只记录已经发生或已经揭示的内容。填表模型根据正文填写事实、角色知情情况和当前场景；作者真相保留在插件的作者资料里。事实表中的「存疑」说法与「已核实」事实不同，人在现场也不自动代表已经知情。

已有线索的标签和登记口径在「修改线索」里改。想让 AI 重新写某一条，先清空它的框，再点「开始自动填写」，只重新生成清空的那几条，改完点保存写进表格。

填表模型写的「依据」是故事里的时间和情节（如「周一晚 码头仓库 看守交出账本」），不写楼层号：数据库交给它的对话不带楼层编号，以前写出的「第1楼」「第2楼」只是那一批里的序号。旧聊天点一次「创建模板」就换成新的说明。

三张线索表建议每楼填写。一个节点可以进行多楼，不要求每轮都有发现，也不会因为已经开放就自动算作完成。离开调查时，控制表写「无」或配置的离场值；空白不等于明确离场。执行页可检查实际读到的表格与焦点。不要在另一个聊天里准备模板后直接套用旧绑定，应在准备游玩的聊天里操作。

## 多条剧情线一起使用

主线依次进行，支线默认同时 1 条，可调为 2 条。还没开始的线按条件和排队规则给出入口提示；玩家真正进入、填表留下证据后才开始，不会因为提示过就算开始。名额已满时，顶端小条提供切换；提示一直保留到确认或关闭。单条暂停和「暂停全部支线」分别管理，不清掉已获得事实。

长文导入可以选「多条支线」，整理后在审阅页逐条检查：外层选线，内层按线信息和各阶段翻页，可直接改字段，也可在对应页写意见让模型修改。已保存的线在大纲页点「审阅修改」继续修改。读关系表等条件时显示现在读到的值；表或列不存在会提示，档位顺序不明确时请先核对，也可改为手动开始。

表格中的场景目录随当前可用入口和场景同步，不需要手动复制。新模板的目录会写入种子行，让第一次填表前也有入口。

事实行按进度建：一条线开始时只建眼前这一步和下一步的行，前一步登记以后再往后建，后面的结局等不会提前出现在表里。下一步只是空行，正文仍然只拿到当前这一步的材料。一次填表里连走三步时，第三步没有行，要手动补记。没有中性标签的事实会提示准备标签。

已结束的线会自动收起：线完成或放弃（单条暂停满3个有效回合也算）、之后又有一次真正的填表，它独用的事实行和知情行就移进插件记录，从表格删除，剧情判断不受影响；还有没结束的线要读的行留在表里。收起后顶端提示「已收起结束的剧情线」，点「恢复」就放回去；放回过的线不再自动收，要收从那条线的「⋯」里手动收。数据库分组填表时，等表格安静半分钟再收。新模板生成的聊天默认收起，其他聊天在剧情线「已结束」页问一次。也可以在那条线的「⋯」里手动收起或放回表格，或在「运行设置」里关掉。跑团项目不收起。

SQLite 存储下，剧情推进（数据库的推进预设）会被复制成「原名（线索模式）」并切到这个聊天，多判断一件事：玩家这一轮走进了哪个场景。走进去的那一轮就给这个场景的材料，不用等下一次填表。跑团项目和原生存储不复制、不切换，照填表判断场景。数据库偶尔没把这一轮的推进结果存到用户消息上（诊断页会写「本轮没读到剧情推进的结果」），这一轮就照填表判断场景，下一轮再给材料。

大纲里写了时间条件时，推进还会判断玩家这一轮有没有明确跳过一段时间（睡到第二天、等到晚上、几天后、直接说了日期或时刻）。跳了的话，这一轮就按跳到的时间算条件，按时间开放的场景当轮就能提示，不用等填表写进新时间。只用于这一轮，不改表格，真实时间仍由填表写；只比表格里记的时间晚才用。正常聊天、走动带来的时间流逝不判断，照常等填表。要用这个功能，时间绑定要指向一张只有一行的表（比如全局表）。

同一场景连续进行了多轮时，插件用本地记录提供承接提示。玩家离开再回来、暂停再恢复都按有效楼层记录计算，不另调模型。表格记了未经本插件提供的发现时，执行页会提示保留或作废；作废和解除作废的含义见升级说明。

## 提前登记和手动纠错

每次填表后，插件只检查新登记的线索：前面的条件按顺序能走通就记下；走不通的（比如结局在前面几步还没完成时就被登记），在 SQLite 存储模式下会把表格改回「未获得」，执行页「需要处理」出现「提前登记已撤回」。作者顺序写错、玩家确实先查到了时，点「保留这次登记」，按原来的登记（存疑仍是存疑）恢复。暂停的线、已经完成的线不挡新登记。升级后第一次打开的老聊天，表里现有的登记全部照旧算数。

节点菜单里的「手动标记完成」会列出这一步表里还没登记的线索，选已核实、存疑或没拿到；后面的条件要某人知道或核实时，在同一个框里勾选。「标为未完成」清掉这一步的登记，之后按表格重新判断；完成条件不只看线索时会说明原因，可以改成「一直按未完成」。线索菜单的「确认」可以选已核实或存疑，「作废」会把表格改回未获得。手动补记、确认和保留的登记照表格判断，不会再被当成正文自行编造来问，补记时写的原因记在操作记录里。原生存储模式下这些操作只改插件的判断，不改表格。

## 抉择与结局（实验）

在设置 → 高级勾「抉择与结局（实验，线索模式）」后才生效；不勾时，大纲里写了也会被忽略，插件和以前一样。跑团项目不使用。

**抉择**：在关键节点上写「抉择」，列出 2～4 个行动。玩家走到这里时，正文停在需要决定的地方，输入框上方出现卡片。点一个行动，会在输入框末尾加一句「我决定……」，玩家接着写自己的动作再发送；也可以点「我有别的打算」自己写，或者「收起」。卡片没出现时，在执行页「当前抉择」里点「打开」；正文已经自己把事办了，点「标为已处理」。

```yaml
抉择:
  情境: 雨夜的仓库，前门有守卫，后门虚掩着
  选项:
    - 行动: 绕到后门，找机会潜进去
      方向: 等守卫换班，从后门摸进去
      风险: 普通
      有利: [{事实: F_换班}]
      用: 身手
      结果: {顺利: 悄悄带出了人, 有代价: 人带出来了，但被看清了脸, 失败: 被发现，人被连夜转走}
    - 行动: 去找管事谈一笔交易
```

- 选项编号不用写，保存后自动补上，之后不变。
- 写了「风险」的行动，发送时插件掷两颗六面骰，加上加值：拿到「有利」里的线索各 +1，「不利」各 -1，难度容易 +1、困难 -1，「用」写的属性按它的值加；总加值最多 ±3。合计 10 以上顺利，7～9 有代价，6 以下失败。正文只拿到这一档的结果，没选的行动和别的档位不会给正文。用户消息旁有个小骰子，点开能看骰面和加值。
- 「有代价」要真的推进目标，只是付出代价；「失败」要写出接下来的处境，并让后面有路可走。
- 选择和骰子记在玩家发出的那条消息上：重 roll、切换回复版本结果不变；删掉那条消息就作废，可以重选。
- 自己想办法（「我有别的打算」）不掷骰，正文按情境写。关键结果（如「人质获救」）写成普通线索，填表登记后，读这条线索的剧情照常开放。

**后续读选择**：开放条件里写 `{抉择: 节点id, 选了: 选项id}`、`{抉择: 节点id, 结果: 失败}`，两项也可以写在一起。还可以写 `{其中至少: 3, 条件: [ … ]}`，表示下面几条满足至少 3 条（适合衡量调查是否周全）。作者检查会提示「必需节点只在某一档才开放」这类会卡住主线的写法。

**属性**：执行页「当前抉择」→「属性…」，最多 5 个，名字自定。填了表格路径（如 `属性表/主角/口才`）就读表，没填就在这里给本聊天设值（-1～+3）。读不到时骰子明细里会写明原因，按 0 算。

**收尾**：在最后一个节点写「收尾」。结局按顺序列出，第一个条件满足的就是它，最后一个不写条件（默认）；尾声分段，每段按顺序挑一个版本。

```yaml
收尾:
  结局:
    - {名称: 账本到手, 条件: {事实: F_账本}, 要点: 老周把账本交了出来}
    - {名称: 暂时平息, 要点: 事情暂时没有结果}
  尾声:
    老周:
      - {条件: {表: 重要角色表/老周/状态 == 死亡}, 要点: 码头工人为老周守了七天灵}
      - {要点: 老周回到码头}
```

- 收尾节点开放、这一轮回复写完后，出现「结束这段故事 / 再待一会儿」。点结束会在输入框加一句，发送时定下结局，正文写一次尾声；之后继续聊只保留一句「故事已收尾」。
- 结局要读的依据读不到（缺表、缺列）时不会自动定结局，执行页会列出读不到的依据，可以修好再收尾，或点「按现有记录收尾」。没做过的抉择算「没发生」。主结局写整体局势，具体人物的命运写在那个人物的尾声段里，避免两处说法矛盾。
- 大纲页「⋯」→「结局预览…」：假设选了什么、骰出什么、拿到哪些线索、表格某一格满不满足，看会落到哪个结局。只在这里算，不写进聊天和表格。

**用 AI 写**：开关打开时，长文导入会按原文起草抉择和收尾（原文写了「玩家在这里要做选择」「几种结局」才写）；「AI 写第 N 卷」在要求里写明要抉择和结局就会写；审阅修改、改写后续会原样保留已有的抉择。写完看一遍。

完整的写法、条件、示例和常见问题见 [抉择写作指南](抉择写作指南.md)。

## 搬到别的酒馆、和角色卡一起发布

数据管理页「导出项目」选一个项目：「导出大纲」只有大纲 YAML；「导出完整项目」还带上线索标签和登记口径、保密名单、推进方式和注入设置，人设、设定可选。作者备注原样保留，它们不会发给正文和填表模型。讨论记录、聊天进度和导入草稿不带。

在别的酒馆点「新项目」，选「从文件导入」。导入总是建成新项目，和已有项目重名时名字后面加「（导入）」，不覆盖原项目。线索表格属于数据库模板，不在项目文件里：在要用的聊天里点执行页的「创建模板」建表，已有线索表就点「补全表格」，标签会直接填好，不用重新生成。大纲改过的线索除外，它的标签要重新准备。

卡作者也可以把项目直接写进角色卡：打开这张卡的聊天，在「导出完整项目」的弹窗里点「写进角色卡」。插件只在卡里加自己的一项，卡里原有的正则、脚本、世界书都不动；之后在酒馆里导出这张卡，剧情项目就跟着卡走。再写一次就是更新。卡里有完整大纲，玩家能从卡文件里看到剧情安排。

玩家导入带剧情的卡、打开它的聊天时，插件会提示「这张角色卡带有剧情项目」，点「导入」后这张卡的聊天都用这个项目；也可以在「新项目」里点「从角色卡导入」。作者更新了卡、玩家重新导入卡以后，插件提示「有新版本」，点「更新」：项目还是原来那个，各聊天的进度接着用，已经走过的剧情不变，新增和改动的剧情按新大纲继续，旧大纲存进修改历史。线索模式下，执行页如果出现「修改线索」或「补全表格」，照提示点一下，表格就跟上新大纲。

## 与数据库插件的关系

本版使用官方 shujuku 的读表、模板、回调及写表接口，已移除实验联动接口。线索编号、标签、登记口径和场景目录通过配套模板提供；插件使用已经提交的表格状态。自动确认进入还会读取官方填表记录和数据库隔离标识，这部分依赖宿主的数据结构；读不到证据时不会把一次路过算作进入，可以手动开始。

上一轮填表尚未结束就发送下一轮，正文可能暂时使用旧状态；等表格填完再继续即可。每楼填表缩短更新间隔，并不代表填表请求会立即结束。回复未达到数据库的 `autoUpdateTokenThreshold` 阈值时可能不触发填表；删除模板预设也不等于恢复全局模板。

## 哪些操作会调用模型

- 正常线索推进：读取已提交表格并临时注入，不额外调用模型。正文生成和数据库原有填表请求照常进行。
- 大纲推进：保留原有按设置间隔检测进度的请求。
- 人设条件：大纲模式随定期检测；线索模式点击「立即检测」时检查，可与焦点场景共用一次请求。手动切换、跟随阶段和读数值无需模型。
- 讨论、AI 写设定／大纲、改写、修正格式、长文整理、自动填写事实标签：执行对应操作时调用配置的模型。长文整理和多卷写作可能连续请求多次。
- 请求核验、规则判断、模式切换、新手教程：本地处理，不调用模型。

## 资料与正文提示

`<仅作者>…</仅作者>` 内容不会由本插件的运行时投影注入正文。世界书原条目如果仍然开启，酒馆仍可能从原条目注入同一份资料。导入世界书时请按实际用途选择公开设定或仅作者资料，并检查原条目是否应该继续开启。

正文写作提示已经内置，包含角色知情边界和剧情推进要求，可在设置页修改或关闭。通常不需要再复制 `templates/正文预设条目_线索推进.md`；如果另外放进正文预设，关闭插件内相同提示，避免重复。

大纲模式和线索模式共用表格。切换模式只改变插件如何读取剧情和生成注入内容，不删除线索表。不同模式的进度分别保留。

## 测试范围

自动测试覆盖源代码、实际构建包、模拟酒馆宿主、官方数据库路径以及人设与线索的组合。真实酒馆中的模型表现、填表准确性、swipe 后的数据库状态和主题布局仍需实测确认。
