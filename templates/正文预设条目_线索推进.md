# 正文预设条目：线索推进

> **不必再手动粘贴。** 插件会随每轮剧情材料自动附带正文通用提示（`<knowledge>` 角色知情、`<progression>` 剧情推进），换卡、换酒馆预设也能直接用；内容可以在设置页「注入内容 → 正文通用提示 → 编辑」里改写或关掉。下面这条更细的线索使用规则仅供参考。

这是一条可以单独粘贴进酒馆正文预设的提示词条目。它告诉正文模型怎么使用剧情注入器在线索推进模式下注入的 `<剧情参考>` 材料。不会增加任何模型调用。

**适用范围**：只在线索推进模式下需要。条目开头写了生效条件：本轮材料里出现线索模式特有的字样时才适用。所以项目切回大纲推进时，条目不会约束大纲模式的阶段材料。即便如此，只用大纲推进的预设也建议不加这条。

**放置位置**：正文预设里，放在世界书和角色设定之后、聊天记录之前，作为 system 角色的普通条目。预设里已有的「不要替用户行动」「说法要标明来源」「角色只知道自己看到听到的」一类规则请保留，这条只补充和插件材料有关的部分。

**标签名**：下面的条目用的是 `<剧情参考>`。如果你在插件设置里改了标签名，条目里也要一起改。

**还没验证的部分**：这条提示还没在真实酒馆里测过。建议对比这四种情况：
- 日常闲聊：不应该硬扯回主线；
- 中途离场又回来：离开时不应揭示发现，回来后接着演；
- 多楼调查只完成了一部分：已经得到的不重复揭示，没得到的不提前给；
- 玩家主动做了一次足以获得线索的明确行动：**应当允许当楼就得到结果**，不要硬拖到下一楼。

观察正文是否抢推剧情、替用户行动、重复揭示同一个发现，或者把「尚未发生」的内容写成已经发生，再据此调整措辞。

## 条目正文（复制下面这一段）

```
【线索材料的使用方式】
本轮 <剧情参考> 里出现「本轮可演的场景材料」或「目前可以去做的事」时，按以下规则使用；没有出现时，这一条不适用。<剧情参考> 只给你看，不要在正文里提到它，也不要复述成清单或剧情汇报。

地点和入口说明角色可以去哪里、可以做什么；是否已经到达，以用户的行动和已经发生的正文为准。

围绕玩家已经作出的选择，写出这一步自然产生的结果。玩家只打了招呼，对方可以继续闲谈；玩家明确举起灯查看锁芯，而撬痕确实清楚可见，就可以在这一楼写出观察结果。还缺一步调查、一个证据或玩家的决定时，就在那里停下，下一步由玩家选。「可能获得的发现（尚未发生）」只在正文实际完成相应的调查、交谈或行动时揭示；没做到、失败、离开或转去做别的事，就不要揭示，也不要让任何角色表现得已经知道。

只有入口的分支（「可以去做的事」），可以写到场、接触人物和开始行动；具体的线索，等相应材料开放后再揭示。「已经获得的发现」不要再安排成第一次发现。已经演过的证词和说法，沿用原话、来源和听到的人，不要写成已证实的事实。写着「表格没有记录具体内容」或「知情范围未记录」的条目，沿用正文已经演出的内容和知情关系，不要自己补充；其他角色要经过实际告知或展示才会知道。
```

## 和插件、填表规则的关系

- 具体有哪些事实、场景和候选发现，每一轮都由插件按表格状态提供。这条预设只放通用的协作规则，**不要把作者剧情写进预设**。
- 这条预设和填表规则是一致的：正文只写实际发生的事，填表只按正文记录。「尚未发生」的内容不会被记成已获得。
- 数据库前置推进任务的提示词里如果有「本轮推进到某某事件」「本轮完成某某」一类的要求，要改成「可以推进，但由用户的行动决定」，否则会和这条预设冲突。前置任务看不到插件的场景材料，它有没有抢推剧情，要看它的实际输出。
- 角色共用同一个正文模型，所以知情控制只是提示层面的约束，不能保证角色绝对不会「全知」。
